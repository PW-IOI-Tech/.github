# Governance

This document defines the governance model for all repositories under
**PW Institute of Innovation – Open Source (PW-IOI OSS)**.

It explains roles, responsibilities, and decision-making authority to ensure
clarity, fairness, and long-term sustainability.

---

## Guiding Principles

- Open collaboration and transparency
- Merit-based contribution recognition
- Clear separation between contributors and decision-makers
- Long-term maintainability over short-term velocity
- Respectful and inclusive community participation

---

## Roles

### 1. Contributor

**Who:**
Anyone who contributes to a project via issues, discussions, or pull requests.

**Responsibilities:**

- Follow repository guidelines
- Use issue and PR templates
- Write clear, maintainable code
- Respond to review feedback respectfully

**Permissions:**

- Fork repositories
- Open issues and pull requests
- Participate in discussions

Contributors do **not** have direct write access to repositories.

---

### 2. Reviewer

**Who:**
Trusted contributors who assist maintainers by reviewing pull requests.

**Responsibilities:**

- Review PRs for correctness, clarity, and standards
- Provide constructive feedback
- Help maintain project quality

**Permissions:**

- Review pull requests
- Comment and suggest changes

Reviewers **cannot** merge pull requests.

> Reviewer status is project-specific and revocable.

---

### 3. Maintainer

**Who:**
Individuals responsible for the health and direction of a specific project.

This may include:

- Project leads
- Long-term contributors selected by the Core Team

**Responsibilities:**

- Review and merge pull requests
- Manage releases and versions
- Maintain documentation and issues
- Enforce contribution standards
- Act in the best interest of the project

**Permissions:**

- Write access to repositories
- Merge pull requests
- Manage issues and labels

Maintainers are accountable to the **Core Team**.

---

### 4. Core Team

**Who:**
Organization-level coordinators appointed by **PW Institute of Innovation**.

This group may include:

- Program coordinators
- Institutional maintainers

**Responsibilities:**

- Define organizational standards and policies
- Approve new projects under the organization
- Appoint and remove maintainers
- Resolve escalated conflicts
- Protect the long-term vision of PW-IOI OSS

**Permissions:**

- Admin access to repositories
- Control over organization settings
- Final decision-making authority

> Core Team membership is **institutional and internal**
> and is **not open for contribution-based promotion**.

---

## Project Ownership

- All repositories are owned by **PW Institute of Innovation – Open Source**
- Accepted student projects become organizational assets
- Original authors are credited but do not retain exclusive control
- Projects remain open for community contribution

---

## Decision Making

| Decision Type                 | Authority   |
| ----------------------------- | ----------- |
| Code changes (PRs)            | Maintainers |
| Releases                      | Maintainers |
| Maintainer appointment        | Core Team   |
| Project acceptance/removal    | Core Team   |
| Org-wide standards & policies | Core Team   |

---

## Conflict Resolution

1. Attempt resolution through discussion on the issue or PR
2. Escalate to project maintainers if unresolved
3. Final escalation to the Core Team

All decisions should prioritize:

- Respect
- Project health
- Community trust

---

## Amendments

This governance model may evolve as the organization grows.

All changes to this document must be approved by the **Core Team**.

---

## Code of Conduct

All members and contributors must follow the organization’s
**Code of Conduct**.

Violations may result in warnings, contribution restrictions,
or removal from the organization.
